# 한글과 영문 README 운영 설계

## 배경

NetBox Cloud Inventory는 사내 인프라 정리 가능성을 검증하는 사이드 프로젝트이면서 공개 오픈소스 저장소다. 현재 `README.md`는 한글로만 작성되어 국내 사용자는 쉽게 읽을 수 있지만 GitHub와 Python 패키지 메타데이터에서 기본으로 노출되는 문서가 영문 사용자를 지원하지 않는다.

하나의 파일에 두 언어를 연속으로 배치하면 문서가 길어지고 같은 내용을 두 번 수정해야 하는 범위가 불명확해진다. 언어별 파일을 분리하고 상단 전환 링크와 동일한 섹션 구조로 운영한다.

## 목표

- GitHub와 패키지 메타데이터에서 영문 README를 기본으로 제공한다.
- 기존 한글 내용을 별도 README로 빠짐없이 보존한다.
- 두 문서에서 언어를 한 번의 클릭으로 전환할 수 있게 한다.
- 실행 명령, 지원 범위, 보안 주의 사항이 두 언어에서 동일하게 유지되게 한다.
- 향후 기능 변경 시 두 README를 같은 커밋에서 갱신하는 운영 원칙을 명시한다.

## 파일 구조

### `README.md`

공개 저장소와 Python 패키지 메타데이터의 기본 영문 문서다. `pyproject.toml`의 `readme = "README.md"` 설정은 변경하지 않는다.

문서 최상단에는 다음 언어 전환을 표시한다.

```markdown
[한국어](README.ko.md) | English
```

### `README.ko.md`

기존 한글 README의 역할을 이어받는다. 문서 최상단에는 다음 언어 전환을 표시한다.

```markdown
한국어 | [English](README.md)
```

두 파일은 저장소 루트에 함께 둔다. 언어별 하위 디렉터리나 한 파일 안의 중복 언어 섹션은 사용하지 않는다.

## 콘텐츠 동등성

두 README는 다음 섹션을 같은 순서로 유지한다.

1. 프로젝트 소개와 현재 PoC 상태
2. 빠른 시작
3. 환경만 실행하고 실제 Export 업로드
4. 합성 데모 데이터 적재
5. 전체 통합 검증
6. 종료와 초기화
7. 목표
8. 1차 범위와 후속 범위
9. 수집 방식
10. 정규화 모델과 핵심 원칙
11. 운영 고려 사항
12. 프로젝트 상태
13. 설계문서
14. 라이선스

명령어, 파일 경로, URL, Parser 프로필 ID, 환경 변수 이름, 리소스 유형은 번역하지 않는다. 설명 문장과 제목만 각 언어에 자연스럽게 작성한다.

기능이나 실행 절차를 바꾸는 커밋은 두 README를 함께 수정한다. 한 언어에만 적용되는 안내가 필요하면 다른 언어 문서에도 해당 안내의 존재와 언어를 표시한다.

## 링크 정책

- 두 README의 언어 전환 링크는 상대 경로를 사용한다.
- 저장소 내부 파일 링크는 두 README에서 동일한 상대 경로를 사용한다.
- 한글로만 제공되는 `docs/manual-import.md`는 한글 README에서 `수동 Import 운영 가이드`, 영문 README에서 `Manual import operations guide (Korean)`으로 표시한다.
- 영문 README의 설계문서 목록은 문서 제목 뒤에 `(Korean)`을 표시해 실제 제공 언어를 숨기지 않는다.
- 외부 URL과 로컬 서비스 주소는 언어별로 바꾸지 않는다.

## 번역 원칙

- 문장 구조를 직역하기보다 오픈소스 기술 문서에서 자연스러운 영문을 사용한다.
- `NAVER Cloud Platform`과 제품 이름은 공식 표기를 유지한다.
- `공공`은 NCP 환경 설명에서 `government`, `민간`은 `commercial`로 설명한다.
- `장부`는 문맥에 따라 `inventory` 또는 `system of record`로 표현한다.
- `수동 Import`는 기능 이름이 드러나도록 `manual import`로 표현한다.
- 경고 문장은 데이터 삭제나 보안 영향이 영문에서도 약화되지 않게 유지한다.
- 사용자 요청에 따라 한글 문서와 영문 문서 모두 가운뎃점 문자를 사용하지 않는다.

## 검증

- 두 README의 최상단 언어 링크가 서로를 정확히 가리키는지 확인한다.
- 두 README의 Markdown 내부 상대 링크 대상이 존재하는지 확인한다.
- 코드 블록의 실행 명령과 URL이 두 언어에서 일치하는지 비교한다.
- Parser 프로필 목록과 지원 범위가 두 언어에서 같은지 비교한다.
- `pyproject.toml`이 계속 영문 `README.md`를 가리키는지 확인한다.
- Ruff, mypy, pytest와 기존 Schema 검증을 다시 실행해 문서 변경이 빌드와 패키지 메타데이터에 영향을 주지 않는지 확인한다.

## GitHub PR 반영

현재 `feature/local-workflow-split` 브랜치와 Draft PR에 다음 변경을 추가한다.

- 기존 한글 `README.md`를 `README.ko.md`로 이동
- 영문 `README.md` 추가
- 두 파일 상단 언어 전환 링크 추가
- 설계문서 목록에 이 다국어 운영 설계 추가
- 검증 결과를 기존 Draft PR 설명에 보강

별도의 PR은 만들지 않고 현재 Draft PR을 갱신한다.
